# STENO — контекст для нативных приложений (macOS / Windows / iOS / Android)

Документ фиксирует, что из браузерной версии переносится в нативные клиенты, что придётся
переписать и какие контракты нужно сохранить, чтобы приложения были совместимы по данным и
поведению. Основан на коде ветки `feature/i18n-video-endpoints-downloads`.

## 1. Что уже платформенно-независимо

| Часть | Где | Как использовать в нативных |
|---|---|---|
| Строки интерфейса, 13 языков, 297 ключей | `src/i18n/locales/*.ts` | Источник истины — `en.ts`. Конвертировать скриптом в `.strings`/`.xcstrings` (Apple), `strings.xml` (Android), `.resx` (Windows). Плейсхолдеры `{name}` сохранить, привести к формату платформы. Набор ключей и плейсхолдеров проверяется на совпадение со словарём `en` |
| Формат результата | `Segment`, `TranscriptResult`, `HistoryItem` в `src/types/index.ts` | Общая JSON-схема; позволяет экспорт/импорт истории между клиентами |
| Экспорт TXT / TXT со спикерами / SRT / VTT | `src/lib/exporters.ts` | Простая логика на `Segment[]` — портировать 1:1 |
| Облачные движки OpenAI / Groq / Deepgram | `src/lib/cloudEngines.ts`, `api/routes/proxy.ts` | Нативный клиент ходит к провайдеру напрямую (CORS не нужен), прокси не требуется |
| Произвольные OpenAI-совместимые сервисы | `src/lib/customEndpoints.ts` | Контракт ниже (раздел 3) |
| План скачивания моделей | `src/lib/modelPlan.ts`, `src/lib/hfTree.ts` | Логика выбора файлов репозитория Hugging Face и проверки хэшей переносима |
| Логика диаризации (кластеризация, привязка к сегментам) | `src/lib/diarize.ts` | Алгоритм переносится; инференс заменить нативным рантаймом |

## 2. Что переписывается под платформу

| Возможность | Браузер сейчас | macOS | Windows | iOS | Android |

| Локальный ASR | transformers.js + ONNX Whisper, WebGPU / WASM | whisper.cpp (Metal / Core ML) или ONNX Runtime | whisper.cpp (CUDA / Vulkan / DirectML) или ONNX Runtime | whisper.cpp + Core ML | whisper.cpp / ONNX Runtime (NNAPI) |
| Локальная диаризация | pyannote segmentation + WeSpeaker, ONNX | ONNX Runtime / Core ML | ONNX Runtime (DirectML) | ONNX Runtime / Core ML | ONNX Runtime |
| Локальный LLM | Qwen3 (ONNX) | llama.cpp / MLX | llama.cpp | llama.cpp (ограничить размером памяти) | llama.cpp |
| Декодирование аудио/видео | Web Audio + ffmpeg.wasm | AVFoundation | Media Foundation / ffmpeg | AVFoundation | MediaCodec / ffmpeg |
| Запись микрофона | `getUserMedia` | AVAudioEngine | WASAPI | AVAudioSession | AudioRecord |
| Системный звук / звук встреч | звук вкладки через `getDisplayMedia` | ScreenCaptureKit | WASAPI loopback | недоступно (ограничение платформы) | MediaProjection (Android 10+, не для всех приложений) |
| Запись видео | `MediaRecorder` (экран, камера) | ScreenCaptureKit / AVCaptureSession | Windows.Graphics.Capture | ReplayKit / AVCaptureSession | MediaProjection / CameraX |
| Наблюдение за папкой | File System Access API, только пока открыта вкладка | FSEvents + security-scoped bookmarks | `ReadDirectoryChangesW` | не поддерживается; Share Extension | SAF + WorkManager |
| Фоновая работа | нет | LaunchAgent / menu-bar app | служба / tray | BGProcessingTask (ограниченно) | foreground service |
| Хранилище | `localStorage` + IndexedDB | SQLite / файлы | SQLite / файлы | SQLite / файлы | Room / файлы |
| Секреты (API-токены) | `localStorage` | Keychain | DPAPI / Credential Locker | Keychain | Keystore |

Решения, которые стоит принять до старта:

- **Общий движок.** Вариант «ядро на Rust/C++ (whisper.cpp + ONNX Runtime) + тонкие UI-оболочки»
  даёт единую логику очереди, загрузок и диаризации на четырёх платформах. Альтернатива — Tauri / Electron для
  десктопа и отдельные нативные мобильные клиенты.
- **Формат моделей.** Whisper в браузере — ONNX из `onnx-community`. whisper.cpp использует
  GGML/GGUF. Нужен либо второй список моделей, либо единый рантайм (ONNX Runtime).
- **iOS и системный звук.** Запись звука других приложений на iOS невозможна; сценарий «встреча» на iOS —
  только микрофон или загрузка файла.

## 3. Контракты, которые нужно сохранить

### 3.1. OpenAI-совместимый сервис (`customEndpoints.ts`)

Поля `CustomEndpoint`: `id`, `name`, `baseUrl` (обычно заканчивается на `/v1`), `apiKey` (опционален), `viaProxy`
(«через сервер приложения»), `models` — выбранные модели `{ id, kind: asr | llm }`, `available` — последний полученный
список моделей сервиса.

Вызовы:

- список моделей — `GET {base}/models`;
- распознавание — `POST {base}/audio/transcriptions` (multipart: `file`, `model`, `response_format=verbose_json`,
  `language` — если задан и не перевод, `prompt` — подсказка из справочников, не длиннее 896 символов). Если сервис
  не поддерживает `verbose_json`, повтор с `response_format=json` (тогда без сегментов). Перевод в английский —
  `POST {base}/audio/translations`;
- текст — `POST {base}/chat/completions`.

Ссылка на модель в настройках — строка `customModelRef(endpointId, modelId)`; разбирается `parseCustomRef`.
Режим «через сервер» нужен только браузеру (обход CORS); в нативных клиентах ходить напрямую.

Коды ошибок (ключи `ep.err.*`): сеть, прокси, авторизация (401/403), HTTP-ошибка, пустой список моделей.

### 3.2. Загрузки моделей (`downloads.ts`)

Состояния задания: `queued` → `running` ⇄ `paused` → `done` | `error`. Требования к нативной реализации:

- последовательная очередь, по одной загрузке за раз;
- возобновление с того же байта (HTTP `Range`), в том числе после перезапуска приложения;
- единый прогресс по байтам всех файлов модели, а не среднее по файлам;
- проверка SHA-256 после скачивания; при несовпадении — повторная загрузка только повреждённого файла;
- проверка свободного места до начала (на сборку файла из частей нужен двойной объём);
- отмена удаляет частичные данные.

### 3.3. Данные пользователя

Ключи хранилища браузера (удобно сохранить имена как идентификаторы в схеме экспорта):

| Ключ | Содержимое |
|---|---|
| `steno.settings.v1` | настройки, в том числе язык интерфейса `uiLang` (по умолчанию `en`) |
| `steno.keys.v1` | API-ключи провайдеров |
| `steno.endpoints.v1` | произвольные сервисы |
| `steno.history.v1` | `HistoryItem[]` (тексты, сегменты, имена спикеров) |
| `steno.glossaries.v1`, `steno.llm-buttons.v1`, `steno.llm-model.v1` | справочники и LLM-кнопки |
| IndexedDB `steno-audio` | исходные файлы истории |
| IndexedDB `steno-downloads` | состояние и части загрузок |

В нативных клиентах ключи и токены хранить в системном хранилище секретов, а не в обычных настройках.
Перенос между устройствами — экспорт/импорт JSON без секретов.

## 4. Поведение, которое должно совпадать

- Язык интерфейса: по умолчанию английский, меняется в настройках; язык браузера/системы не определяется
  автоматически. Язык речи записи выбирается отдельно в панели движка.
- Отмена: любой запущенный процесс (декодирование, загрузка модели, распознавание, диаризация, LLM)
  прерывается; задача получает статус «отменена», прежний текст сохраняется.
- Запись: микрофон, звук вкладки/системы, видео экрана, видео камеры; автостоп после 10 секунд тишины;
  у видео транскрибируется только аудиодорожка, видео остаётся в хранилище.
- Ошибка диаризации или таймаут не должны ронять распознавание: этап пропускается со статусом.
- Приватность: в режиме «локально» аудио не покидает устройство; интерфейс всегда показывает, куда уходит файл.

## 5. Рекомендуемый порядок

1. Вынести общее ядро: модель данных, экспортёры, очередь и загрузки, облачные клиенты, схема настроек.
2. macOS и Windows: запись, локальный Whisper, папка-наблюдатель, фоновая работа. Системный звук
   встреч — главное преимущество перед веб-версией.
3. Android: локальный Whisper малых моделей, запись, Share Intent.
4. iOS: микрофон, импорт файлов, облачные движки; локальные модели — ограниченно из-за памяти.

## 6. Открытые вопросы

- Единый рантайм моделей (ONNX Runtime) или whisper.cpp на десктопе и мобильных.
- Нужна ли синхронизация истории между устройствами (требует своего сервера и шифрования).
- Лицензии моделей и бинарных зависимостей при распространении в магазинах приложений
  (pyannote — MIT, WeSpeaker ResNet34 — CC-BY-4.0: требуется указание авторства).
- Порог памяти для локальных LLM на мобильных.

## 7. Версии, диалог для LLM, проекты, облака (добавлено во второй итерации)

### 7.1. Версии расшифровки (`types/index.ts`, `lib/transcript.ts`, `lib/versionStore.ts`)
- `TranscriptVersion { id, createdAt, kind: 'asr'|'llm'|'edit', label, parentId?, text, segments, speakerNames, language?, durationSec, elapsedSec, engineLabel, modelLabel }`.
- Запись истории хранит копию только АКТИВНОЙ версии (`text/segments/speakerNames`, `activeVersionId`); все версии лежат отдельно (в вебе — IndexedDB `steno-versions`, ключ = id записи). Нативные клиенты: отдельная таблица/файл на запись.
- Лимит `MAX_VERSIONS = 15`; при переполнении удаляется самая старая версия, не являющаяся активной и не родительской (`pushVersion`). Старые записи без версий превращаются в одну версию (`legacyVersion`).
- Правки спикеров (`mergeSpeakers`, `splitSegment`, `joinWithPrevious`) — чистые функции над `Segment[]`; время при разделении реплики распределяется пропорционально числу символов, граница привязывается к слову (`snapToWord`).

### 7.2. Формат разговора для LLM
- Строка на реплику: `[mm:ss] Имя: текст` (без диаризации — `[mm:ss] текст`), `toDialog`.
- К системному промпту добавляются правила `formatRules` (структура + «верни в том же виде», если включено «сохранять формат»). Встроенные «свободные» действия (summary, tasks) формат не сохраняют (`free: true`).
- Ответ разбирается `parseDialog`: строки сопоставляются с исходными сегментами по таймкоду, точные start/end и спикеры восстанавливаются; новые имена спикеров попадают в `speakerNames`. Если ответ не похож на расшифровку — `null`, сохраняется плоская версия (без сегментов).

### 7.3. Файл проекта `.steno` (`lib/project.ts`, `lib/projectStore.ts`)
- Байты: `"STENOPRJ1\n"` + `u32 LE` длина заголовка + JSON-заголовок (UTF-8: `format:'steno-project'`, `version:1`, `exportedAt`, `entries[{ item: HistoryItem с versions, audio?: {name,type,size} }]`) + аудио-блобы подряд в порядке `entries`.
- Ошибки разбора: `not-a-project`, `corrupt-project`. Импорт присваивает новый id при совпадении и не затирает существующие записи.

### 7.4. Облачный обмен (`lib/cloud/*`)
- Интерфейс `CloudProvider { connect, disconnect, upload, list, download }`; файлы лежат в папке `STENO` на диске пользователя.
- Dropbox: OAuth PKCE (всплывающее окно), `content.dropboxapi.com` (загрузка до ~140 МБ одним запросом, больше — upload_session кусками по 8 МБ).
- Google Диск: Google Identity Services, scope `drive.file`, resumable-загрузка.
- Яндекс Диск: implicit OAuth, `cloud-api.yandex.net`; CORS хостов загрузки/скачивания не проверен — в браузере возможна сетевая ошибка. В нативных приложениях проблемы нет.
- Redirect URI = `origin + BASE_URL`. Нативные приложения используют свои схемы (loopback / custom scheme / ASWebAuthenticationSession) и свои client id.
- Ключи приложений: `VITE_GDRIVE_CLIENT_ID`, `VITE_YANDEX_CLIENT_ID`, `VITE_DROPBOX_APP_KEY` или ввод пользователем (localStorage `steno.cloud.v1`).

### 7.5. Интерфейс
- Три состояния главной: `start` (источник по центру) → `prepare` (источник + движок + запуск) → `work` (узкая рейка с ярлыками, плеер/текст, колонка LLM; всё в пределах экрана, текст прокручивается внутри блока, активная реплика центрируется только внутри него).
- Для видео/записи экрана превью занимает место зоны перетаскивания. Скорость воспроизведения 0.5–2× с сохранением тона (`preservesPitch`), значение запоминается.
- Статус локальной модели: «загружаем из хранилища браузера — ничего не скачивается» (стадия `storage`), если все файлы уже в кэше; иначе стадия `download`.
- Тема по умолчанию — «Aurora» (стекло, градиентная сетка); выбранная пользователем тема не перезаписывается (`themeChosen`).

## 8. Скриншоты, субтитры, раскладка чтения (третья итерация)

- **Субтитры поверх видео** (`lib/player.tsx`): показывается реплика, активная в текущее время (`subtitleAt`: последняя с `start ≤ t`, видна до `end + 0.4 с`). Подсветка слов оценочная — по доле символов от длительности реплики (`activeWords`); произнесённые слова окрашены, плашка как у активной строки расшифровки. Над видео — имя спикера. Включение запоминается (`steno.subs.v1`). В нативных клиентах — слой поверх видеоплеера с той же логикой.
- **Скриншоты**: кадр текущего времени забирается из видеоэлемента в PNG; если субтитры включены — они «вжигаются» в кадр тем же алгоритмом (`drawSubtitle`). Лента до 12 последних кадров, просмотр, копирование в буфер (`ClipboardItem image/png`), скачивание `имя_чч-мм-сс.png`. Нативно: AVAssetImageGenerator / MediaMetadataRetriever / Media Foundation + буфер обмена платформы.
- **Раскладка работы**: слева колонка «запуск (кнопка + статус + мини-индикатор) → медиа → AI-обработка», справа расшифровка на всю высоту. Подробный список задач скрыт в «Подробности». Пока LLM работает или есть результат, видео сужается (≈24vh); кнопка «увеличить» разворачивает видео и скрывает панель AI. Плеер вынесен из `TranscriptView` в `MediaPane`; расшифровка управляет им через `playerRef` и получает `playerState`.

## 9. Правка текста, развёрнутый результат LLM, связанная прокрутка (четвёртая итерация)

- **Правка реплики**: меняется только `text` сегмента активной версии (`start/end/speaker` не трогаются), `text` версии пересобирается `plainText(segments)`. Пустой текст не принимается. Чтобы сохранить оригинал, сначала «Дублировать версию». Ctrl/Cmd+Enter — сохранить, Esc — отмена.
- **Результат LLM в формате расшифровки**: если ответ разобран `parseDialog`, он показывается теми же строками (таймкод, спикер, текст); иначе — как обычный текст. На десктопе результат можно развернуть вверх на место видео; медиа остаётся в дереве (воспроизведение не прерывается), но скрыто.
- **Связанная прокрутка**: опорная точка — первая видимая строка источника; в приёмнике выбирается последняя строка с `start ≤` этого таймкода, плюс доля прокрученной высоты строки. Короткая блокировка (90 мс) предотвращает «эхо». Нативные клиенты: тот же алгоритм по таймкодам, а не по процентам высоты.

## 10. Поиск, отмена, заметки, экспорт, пословные метки (пятая итерация)

- **Модель Segment** дополнена необязательными полями: `mark` (закладка), `note` (комментарий), `words[{text,start,end}]` (пословные метки). Старые данные остаются валидными; `.steno` переносит поля как есть. При изменении текста реплики `words` сбрасываются (больше не совпадают с текстом).
- **Чистые функции** (`lib/transcript.ts`, покрыты тестами): `findMatches/findInText`, `replaceInSegments`, `removeFillers` (списки междометий по языкам; пустые реплики удаляются, таймкоды остальных не меняются), `diffWords` (LCS по словам), `segmentsFromWords` (реплика заканчивается знаком окончания фразы, паузой > 0,9 с или 28 словами).
- **Отмена/повтор**: снимки `{segments,text,speakerNames}` активной версии, до 60 шагов, сбрасываются при смене версии.
- **Горячие клавиши плеера**: пробел/K — пуск, ←/→ ±5 с, J/L ±10 с, N/P — следующая/предыдущая реплика; Ctrl/Cmd+Z, Shift+Z/Y — отмена/повтор; Ctrl/Cmd+F — поиск.
- **Пропуск пауз**: при воспроизведении, если до следующей реплики тишина > 1,5 с — перемотка к ней (−0,2 с).
- **Экспорт**: Markdown и самодостаточный HTML с закладками, заметками и скриншотами (вставляются после реплики, с которой начинается кадр). Видео с вшитыми субтитрами — запись в реальном времени (canvas + MediaRecorder + звук через AudioContext), WebM; нативно заменяется штатным кодированием (AVAssetWriter, MediaCodec, Media Foundation).
- **Пословные метки Whisper**: опция `wordTimestamps` (по умолчанию выкл.); воркер просит `return_timestamps:'word'`, при ошибке модели откатывается к обычному режиму. Субтитры используют точные слова, если они есть, иначе оценку по символам.
- **Черновик правки** хранится в `steno.draft.v1` и восстанавливается при открытии той же версии.
- **Телефон**: вкладки «Видео / Текст / AI» вместо трёх колонок.

## 11. Меню экспорта, справочники CSV, цвета субтитров, серверный Google Drive, хранилище (шестая итерация)

- **Меню экспорта**: одна иконка загрузки открывает всплывающее меню — TXT/SRT/VTT и Markdown/HTML. Для MD/HTML есть переключатель «со скриншотами/без» (по умолчанию со скриншотами, если они есть) и кнопки «предпросмотр» и «скачать». Предпросмотр: HTML — в sandbox-iframe (`srcDoc`, без скриптов); Markdown — упрощённый рендер (`lib/mdPreview.ts`) с переключением на исходник. Нативно: те же режимы, WebView/QuickLook для предпросмотра.
- **Справочники (глоссарий)**: формат термина `слово = расшифровка`. Редактор хранит сырой текст и разбирает его только при потере фокуса/смене — раньше обрезка пробелов на каждый символ ломала ввод пробела и перенос строки. Импорт/экспорт CSV (`lib/glossaryCsv.ts`): разделитель определяется автоматически (`,` `;` табуляция), кавычки поддерживаются, заголовок (`term`/`слово`) пропускается; один столбец — термин, два — `a = b`; дубли удаляются. Можно добавить CSV в существующий справочник или создать новый (имя — по файлу). Экспорт: `term,replacement`.
- **Субтитры по спикерам**: цвет подсвеченных слов и подписи берётся из `speakerColor(speaker)` (`lib/transcript.ts`), как в списке расшифровки; запасной — жёлтый для реплик без спикера. Действует в плеере и в «вжигании» в скриншоты/видео (`drawSubtitle`).
- **Развёрнутый результат LLM** на десктопе занимает ту же высоту, что и расшифровка: панель запуска скрывается, левая колонка целиком отдана блоку AI.
- **Google Drive через серверные учётные данные**: схема authorization code на сервере (`api/routes/google.ts`). Секрет `GOOGLE_CLIENT_SECRET` остаётся только на сервере; клиенту возвращается короткоживущий access token (`scope drive.file`, `access_type=online`, refresh-токенов нет) через `postMessage` из всплывающего окна. Эндпоинты: `GET /api/google/status`, `/start`, `/callback`. Переменные окружения: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, опционально `GOOGLE_REDIRECT_URI` (иначе строится из заголовков прокси: `<origin>/<prefix>/api/google/callback` — этот URI нужно добавить в Google Cloud Console). Если пользователь ввёл собственный Client ID, используется прежний браузерный поток (GIS). `state` и `base` валидируются (`safeState`, `safeBase`). Нативно: тот же серверный обмен, токен — в защищённое хранилище (Keychain/Keystore/DPAPI).
- **Окно хранилища** (`sections/StorageModal.tsx`): по каждому проекту — оригинальный файл, конвертированный WAV (`wavSize`), версии по типам (оригинальная транскрибация `asr`, результаты LLM `llm`, отредактированные `edit`) с размерами; итоги по категориям, занятое место браузера (`navigator.storage.estimate()`), «осиротевшие» файлы без проекта. Удаление: файл, WAV (`deleteConvertedWav`), неактивная версия, проект целиком. Активную версию удалить нельзя.
- **Менеджер файлов доступен везде**: кнопка с иконкой диска в шапке открывает `StorageModal` на любом экране (старт/подготовка/работа), закрытие — Esc или клик по фону. Из окна можно скачать оригинальный файл, конвертированный WAV, любую версию (TXT; SRT, если есть сегменты) и файлы без проекта. Нативно: пункт меню «Хранилище» + «Показать в Finder/Проводнике» / Share Sheet.
- **Свой сервис: только аудио и свой путь** (`CustomEndpoint.convertAudio`, `asrPath`): при включённой «конвертации» на распознавание уходит WAV 16 кГц моно (PCM16, ≈ 2 МБ/мин), собранный из уже декодированных отсчётов, вместо исходного файла/видео; имя файла — `<имя>.wav`. `asrPath` заменяет `/audio/transcriptions` (только прямой режим). Ошибки 404/405 показывают адрес, на который ушёл запрос. Нативно: то же поле контракта, декодирование — штатными средствами платформы.
- **whisper.cpp server**: `POST /v1/audio/transcriptions` (multipart `file`, `response_format=json|verbose_json`), без `/models` — модель добавляется вручную (id любой, сервис его игнорирует); принимает WAV (другие форматы — только со сборкой с ffmpeg), поэтому включается «конвертировать в WAV». Кнопка «Проверить распознавание» шлёт секунду тишины и показывает ответ/ошибку сервиса. Ручные модели сохраняются при обновлении списка.
- **Свои сервисы: пословные метки и спикеры**. Флажок «пословные метки» теперь и для своего сервиса: добавляется `timestamp_granularities[]=word` (+`segment`) к `verbose_json`; слова берутся из `words` верхнего уровня или `segments[].words` (`word`/`text`) и раскладываются по репликам по времени. Если сервис вернул только текст (json без таймкодов), текст режется на предложения со временем, пропорциональным длине (`sentencesToSegments`) — чтобы локальная диаризация могла разметить спикеров. В «Движке» при отсутствии у сервисов моделей типа «речь → текст» показывается подсказка со ссылкой в настройки.
- **Спикеры вручную**: панель «Спикеры» показывается всегда (даже без диаризации); «+ Добавить спикера» создаёт идентификатор `nextSpeakerId` и сохраняет имя в `speakerNames` (спикер без реплик живёт, пока у него есть имя). У каждой реплики — выбор спикера (в т.ч. «Без спикера» и «Новый спикер»); пустое значение снимает спикера (`speaker` не задаётся). Список спикеров = спикеры реплик ∪ ключи `speakerNames`.
